# Brand assets

Source PNGs supplied by the owner (`source/logo-icon-source.png`, `source/logo-full-source.png`) and derived assets generated by `apps/web/scripts/generate-brand-assets.cjs`.

## What was actually produced, and why it differs from the original plan

CLAUDE.md §15 and this file originally called for `logo-dark.svg`/`logo-light.svg` (separate SVG traces for light/dark backgrounds) plus `icon-1024.png`. Once the real source arrived, tracing turned out to be the wrong tool for this artwork:

- The logo is a **multi-tone geometric mark** (navy `#3A4551`, grey `#8B939C`, cream accent) on a near-white background — not a simple single-color silhouette. `potrace` (bitmap→vector tracing) is built for monochrome shapes; run against this, it would collapse the three-tone separation that makes the mark recognizable. Not attempted — the quality would have been poor, per the owner's own pre-approved fallback ("if SVG tracing quality is poor, use the PNG directly").
- A naive CSS `invert()` for a dark-mode variant (the other pre-approved fallback) was also rejected after checking the actual math: inverting navy/grey/cream produces muddy brown/tan tones, not a clean light-on-dark look. Not used.

**What exists instead:**

| File | What it is |
|---|---|
| `logo-full.png` | Full lockup (icon + "ML TRADING" / "INTERNATIONAL.LTD"), background made transparent via color-keying + autocrop. Used as-is (no SVG). |
| `logo-icon.png` | Icon only, same transparency treatment. |
| `../icon-192.png`, `../icon-512.png` | PWA manifest icons, resized from `logo-icon.png`. |
| `../apple-touch-icon.png` | 180×180, flattened onto the brand `--secondary` surface color (`#F1F3F5`) — iOS renders transparency as solid black, so this one can't stay transparent. |
| `../favicon.ico` | 32×32 + 16×16 PNGs packed into one .ico via `png-to-ico`. |

**Where the light/dark problem actually went:** the login page (E8) avoids it entirely by placing the logo on a light card that sits on top of the brand gradient background, rather than needing a version of the logo that reads directly against a dark or gradient surface. This works for Phase 1's actual need. A true dark-mode-native logo variant (if ever needed — e.g. a dark-surface sidebar header) is deferred; flagged as a known gap, not silently dropped.

## Icon vs. full lockup

- **Icon** = the mark alone, no wordmark — square, works small. Favicons, PWA home-screen icon, browser tab.
- **Full lockup** = icon + wordmark. Login screen, and anywhere there's room to read the business name.

## Regenerating

`node apps/web/scripts/generate-brand-assets.cjs` (from `apps/web`) re-derives everything above from the two source PNGs. Re-run if the source files change.
